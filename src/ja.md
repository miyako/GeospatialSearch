# 4D、ORDA、4D.Vectorによる地理空間検索

Karim Meghraoui（4D Morocco テクニカルサポートエンジニア）

テクニカルノート 26-09

## 概要

現代のアプリケーションでは、ユーザーの地理的な位置に応じたサービスを提供するために、位置情報の活用がますます広がっています。近くのレストランを探す、銀行の支店を見つける、街のホテルを探す、2地点間の距離を計算するといったことは、今では当たり前になりました。こうした機能はすべて、地理空間データの活用に支えられています。

地理空間データとは、地球表面上の位置に関連付けられた情報です。この位置は一般に、緯度と経度という2つの数値で表されます。緯度は赤道を基準とした位置を、経度はグリニッジ子午線を基準とした位置を示します。この2つの値を組み合わせることで、世界中のあらゆる場所を正確に特定できます。

これらの座標を使うと、アプリケーションは2地点間の距離の測定、特定の地理的範囲内にある対象の検索、インタラクティブな地図への情報表示など、さまざまな処理を行えます。こうした処理を総称して地理空間検索と呼びます。

応用分野は多岐にわたります。たとえば次のようなものです。

- ユーザーが都市周辺の見どころを見つけられる観光プラットフォーム
- 顧客に最も近いドライバーを探す配送アプリケーション
- 車両の位置をリアルタイムで追跡する運輸会社
- 指定した地理的範囲内の物件を提示する不動産プラットフォーム
- これらすべての例において、位置情報は検索処理の重要な要素です。

## はじめに

このテクニカルノートでは、4D、ORDA、4D.Vector型を使って構築した地理空間検索機能の実装を紹介します。アプリケーションは、日本の都市と日本国内のさまざまな観光地を収録したデータベースを使用します。ユーザーが選択した都市を起点に、指定した半径内にあるすべての観光地を自動的に検索してそれぞれの距離を計算し、結果をリストとインタラクティブな地図の両方で表示します。

このテクニカルノートの目的は、座標の保存から地図への表示まで、この機能を実装するための各ステップを解説することです。プロジェクトの主要なメソッドを一つずつ取り上げ、4Dのさまざまな機能を組み合わせてシンプルかつ効率的な地理空間ソリューションを構築する方法を示します。

## アプリケーションの全体像

このアプリケーションの原理は比較的シンプルです。各都市と各観光地にはGPS位置がデータベースに保存されており、この座標を使って地点間の距離を計算します。ユーザーが検索を行う際は、まずリストから都市を選択します。この都市が、すべての計算の基準点になります。次に、最大距離をキロメートル単位で指定します。この距離が検索半径になります。

アプリケーションは選択された都市のGPS座標を取得し、データベースに保存されているすべての観光地の座標と比較します。観光地ごとに距離を計算し、その距離が指定した半径以下であれば、その観光地を結果に含めます。これらの処理はすべて、4Dデータベースエンジン内で単一のORDAクエリとして実行されます。

簡単な例で考えてみましょう。ユーザーが京都を選択し、検索半径を50キロメートルに指定したとします。アプリケーションは、登録されているすべての観光地を調べます。京都から18キロメートルの位置にある観光地は結果リストに追加されますが、120キロメートル離れた観光地は含まれません。

結果の観光地は、近いものから遠いものの順に自動的に並べ替えられます。この順位付けにより、ユーザーは最も行きやすい場所をすぐに把握できます。

結果リストに加えて、アプリケーションは選択した地点を表示するインタラクティブな地図を生成します。観光地の位置を地図上に直接示すことで、結果をより理解しやすくなります。

## アプリケーションの地理データ

このアプリケーションでは、情報を都市と観光地という2種類のエンティティで構成しています。日本の都市と観光地の小規模なデータセットは、Wikidataを使って収集しました。都市は検索の基準点となります。各都市は、フランス語・英語・アラビア語・日本語での名称、人口、その都市に関する既知の情報をすべて掲載したページへのWikidata参照など、いくつかの説明的な属性を持ちます。観光地は、ユーザーが検索したい場所を表します。各観光地も、複数言語での名称やWikidata参照など、いくつかの説明的な属性を持ちます。とはいえ、どちらのエンティティにとっても最も重要な情報は地理的な位置です。位置情報がなければ、距離を計算することも地図上に場所を表示することもできません。

![](fig-02)

座標に緯度と経度の2つの数値フィールドを別々に使う従来の方法とは異なり、このアプリケーションでは4D.Vector型を使用しています。これにより、2つの座標を1つの変数にまとめることができます。

例：

```text
[35.0116,135.7681]
```

1つ目の値が緯度、2つ目の値が経度です。

4D.Vectorを使うことには、いくつかの利点があります。

まず、座標を1つのオブジェクトとして扱えるため、コードが読みやすくなります。各メソッドは緯度と経度を別々の引数として受け取る必要がなくなり、両方の値を含むベクトルを直接扱えます。さらに、4D.Vectorのインスタンスは不変（イミュータブル）であるため、緯度や経度が誤って上書きされるリスクを減らせます。

2つの方法（緯度・経度を個別に扱う方法と、1つの4D.Vectorにまとめる方法）を比較するために、2つの座標を受け取って距離を計算する4Dメソッドの宣言を示します。

```4d
#DECLARE ($latitude1 : Real; $longitude1 : Real; $latitude2 : Real; $longitude2 : Real) ->
$distance : Real
```

```4d
#DECLARE($coords1 : 4D.Vector; $coords2 : 4D.Vector) -> $distance : Real
```

この方法は、開発時のミスにも強くなります。緯度と経度を2つの別々の変数に格納していると、うっかり取り違えてしまうことがあります。座標を4D.Vectorのインスタンスとして扱えば、このリスクを大幅に減らせます。

最後に、この方法はアプリケーションの将来的な拡張も容易にします。すべてのメソッドが同じデータ型を使うため、エラーが起こりにくくなり、プロジェクト全体の一貫性も高まります。

## GPS座標の表現

地理座標は、現在のほとんどのGPSシステムで使われている形式である10進数の度（Decimal Degrees）でデータベースに保存されます。

たとえば、京都の座標は次のように表せます。

```text
35.0116
135.7681
```

これらの値は数学的な計算には非常に適していますが、ユーザーにとっては直感的に読み取りにくい場合があります。

特に地図や観光のアプリケーションなどでは、DMS形式（度・分・秒）と呼ばれる、より伝統的な表記を使うほうが望ましい場合があります。

次のような座標は、

```text
35.0116
```

次のようになります。

```text
35°0'42"N
```

この形式は、地図や一部のナビゲーションシステムで一般的に見られる表記に近いものです。

そのため、アプリケーションにはこの変換専用のメソッドが2つ用意されています。

1つ目のメソッドは、緯度または経度の値を度・分・秒に変換します。また、値の符号に基づいて対応する方位（北・南・東・西）も判定します。2つ目のメソッドは、緯度と経度を組み合わせて、次のような完全な表記を生成します。

```text
35°0'42"N 135°46'5"E
```

この変換は距離の計算には使用しません。距離の計算は、完全な精度を保つため、引き続き10進数の座標を使って行います。DMS形式は、ユーザーインターフェースでの地理情報の表示をわかりやすくするためだけに使用します。

## 4Dデータベースへの地理データの読み込み

地理空間検索を実行するには、まず都市と観光地を含むデータセットがアプリケーションに必要です。この情報は、アプリケーションのRESOURCESフォルダーにある次の2つのJSONファイルで提供されます。

- morocco-cities.json：都市の情報を収録
- touristic-sites.json：観光地の情報を収録

JSONはシンプルで軽量な形式で、データ交換に広く使われており、4Dでも完全にサポートされています。人が読んでもわかりやすく、4DではJSON Parse()コマンドを使って直接処理できます。

データの読み込み処理は、データベースの初期化時に一度だけ実行されます。処理を開始する前に、メソッドはテーブルにまだデータが存在しないことを確認します。

```4d
If ((ds.City.getCount()#0) || (ds.TouristicSite.getCount()#0))

    // Data tables `City` and/or `TouristicSite` already contain data.
    return

End if
```

この確認は重要です。テーブルにすでにレコードが存在する状態で読み込みを再実行すると、重複したエントリが作成されてしまう可能性があります。そのため、メソッドは処理を中止し、データがすでに存在することをユーザーに知らせます。

この確認が済んだら、2つのJSONファイルを読み込んでオブジェクトのコレクションに変換します。

```4d
$citiesData:=JSON Parse(File("/RESOURCES/morocco-cities.json").getText())
$touristicSitesData:=JSON Parse(File("/RESOURCES/touristic-sites.json").getText())
```

File().getText()でファイルの内容を読み込み、JSON Parse()でそのテキストを4Dランゲージから直接操作できるオブジェクトのコレクションに変換します。

コレクション内の各オブジェクトは、1つの都市または1つの観光地に対応します。

次に、メソッドは各コレクションを順に処理し、対応するレコードをデータベースに作成します。

都市の場合は、new()関数を使って新しいORDAエンティティを作成します。

```4d
$cityEntity:=ds.City.new()
```

この命令で新しいCityEntityオブジェクトが作成され、JSONファイルから読み込んだ情報が設定されます。

各プロパティをエンティティにコピーします。

```4d
$cityEntity.nameFR:=$cityData.nameFr
$cityEntity.nameEN:=$cityData.nameEn
$cityEntity.population:=Num($cityData.population)
```

各言語での名称やWikidata参照など、その他の属性にも同じ処理を適用します。

ただし、GPS座標には特別な処理が必要です。

JSONファイルでは、座標は2つの値を含む配列として格納されています。

例：

```text
[35.0116,135.7681]
```

アプリケーション内で扱いやすくするため、これを**4D.Vector**オブジェクトに変換します。

```4d
$cityEntity.coordinates:=4D.Vector.new($cityData.coord)
```

この命令により、JSON配列は緯度と経度の値を含むベクトルに自動的に変換されます。

4D.Vector型を使うことには、さまざまな利点があります。座標を扱うメソッドやルーチンの実装が簡単になるだけでなく、4Dデータベースエンジンで保存可能な型として完全にサポートされており、4Dコンパイラーも型を認識するため、構文チェックによってエラーや誤用を検出できます。

![JSONデータをORDAエンティティに読み込む](fig-04)

すべてのプロパティを設定したら、エンティティをデータベースに保存します。

```4d
$cityEntity.save()
```

観光地にも同じ処理を適用します。

このステップが完了すると、地理空間検索に必要なすべての都市と観光地がデータベースに揃います。

このメソッドは、JSONファイルのデータをORDAエンティティに読み込む典型的な例です。

## 2地点間の距離の計算

座標がデータベースに保存されれば、地点間の距離を計算できます。この処理はgeoDistance()メソッドが担当します。このメソッドのシグネチャは非常にシンプルで、2つのGPS座標を受け取り、その間の距離をキロメートル単位で返します。

### 入力の検証

計算の前に、2つのガード節が実行されます。1つ目は、座標が欠落している場合を除外します。

```4d
If (($coordsA=Null) || ($coordsB=Null))
    return Num("INF")
End if
```

2つ目は、各ベクトルがちょうど2つの要素を持っていることを確認します。

```4d
If (($coordsA.length#2) || ($coordsB.length#2))
    return Num("INF")
End if
```

エラーを発生させる代わりに無限大の値を返すのは、意図的な設計です。距離が無限大であれば、その地点はアプリケーションの他の箇所で特別な処理をしなくても、近接検索から自動的に除外されます。

![geoDistance()メソッドの制御フロー](fig-05)

### 単位の変換

座標は10進数の度で保存されていますが、4Dの三角関数はラジアンで動作します。そのため、各要素を使用する前に変換します。

```4d
$latA:=$coordsA[0]*Degree
$lonA:=$coordsA[1]*Degree
```

2つ目の座標の組にも同じ変換を適用します。

### ハーバーサイン公式

続いて、メソッドはハーバーサイン（Haversine）公式を適用します。これは、地球表面上の2地点間の最短経路を求めるための、位置情報システムにおける標準的な手法です。平面上の距離とは異なり、地球の曲率が考慮されます。

この公式からは、2つの位置の間の中心角が得られます。この角度に地球の平均半径を掛けると、距離が求められます。

```4d
return $earthRadius*$centralAngle
```

![ハーバーサイン公式の原理：中心角に地球の半径を掛ける](fig-06)

地球を半径一定の球としてモデル化した場合、WGS84楕円体との誤差は0.5％未満に収まり、近接検索においては無視できる程度です。

### アプリケーションにおける役割

このメソッドはアプリケーションの中核であり、すべての地理空間機能がその出力に依存しています。計算された距離は、検索半径による観光地の絞り込み、近い順から遠い順への結果の並べ替え、そして画面上でユーザーに表示する距離に使われます。

![計算された距離の利用先](fig-07)

## ORDAによる地理空間検索

geoDistance()メソッドが用意できたら、残る作業はこれを使って実際の検索を行うことです。たとえば、ある都市（ここでは「大阪」とします）を中心とした指定の半径（たとえば30km）内にあるすべての観光地を探したい場合、30キロメートルより近い観光地だけが返されなければなりません。

![選択した都市からの距離に応じて、観光地を残すか除外するかが決まる](fig-08)

4Dでは、このようなユースケースにORDA（Object Relational Data Access）で対応します。ORDAは4Dが提供するデータアクセスフレームワークです。ORDAは、保存されたデータをSQLの結果セットとしてではなく、エンティティやエンティティセレクションとして公開します。各レコードは、独自のプロパティとメソッドを持つエンティティになります。観光地にはデータストアを通じてアクセスし、ds.TouristicSiteはデータベース内のすべての観光地を含むエンティティセレクションを表します。

検索メソッドは、基準となる都市と最大距離の2つの引数を受け取り、コレクションを返します。

```4d
#DECLARE($city : cs.CityEntity; $maxDistance : Real)->$sitesWithDistance : Collection
```

1つ目の引数は選択された都市のエンティティ、2つ目はキロメートル単位の検索半径です。検索は4つの段階で進みます。

![検索メソッドの処理順序：引数から結果のコレクションまで](fig-09)

### 引数の検証

検索を実行する前に、メソッドは渡された引数が使用可能であることをアサーションで確認します。

```4d
ASSERT($city#Null)
ASSERT($maxDistance>=0)
```

1つ目のアサーションは都市が指定されていること、2つ目は指定された距離が正の値であることを保証します。これらにより、不正な入力で検索が実行されるのを防ぎます。

### ORDAクエリでのFormula()の使用

検索の中心となるのは、単一のORDAクエリです。

```4d
$sites:=ds.TouristicSite.query(
    Formula(
        geoDistance(This.coordinates;$city.coordinates)<=$maxDistance
    )
)
```

このフォーミュラは、データベースエンジンによってテーブル内の観光地ごとに1回ずつ効率的に評価されます。各観光地について、次の2つの値を比較します。

- 調べている観光地の座標（This.coordinatesとして参照）
- 選択された都市の座標（$city.coordinatesとして渡される）

観光地は、都市までの距離が$maxDistance以下である場合、つまり検索範囲内にある場合に残されます。

この方法が効率的なのは、レコードをメモリに読み込んでアプリケーションのコードで1件ずつ測定する必要がないためです。絞り込みはORDAエンジンに任されます。

### 近い順の並べ替え

地理的な検索では、結果を最も近い場所から遠い場所の順に表示することが求められます。並べ替えの基準にも、同じ距離の式を使います。

```4d
.orderByFormula(
    Formula(
        geoDistance(This.coordinates;$city.coordinates)
    )
)
```

条件に合う観光地ごとに距離が計算され、その値で並び順が決まります。たとえば、京都周辺を検索すると次のような結果が返されます。

| 観光地 | 距離 |
|---|---|
| 八坂神社 | 1.3 km |
| 清水寺 | 2.4 km |
| 東大寺 | 36.4 km |

これにより、最も近い場所がリストの先頭ですぐにわかります。

### 結果のコレクションの作成

検索が完了すると、メソッドは条件に合った各観光地とその距離を組にしたコレクションを作成します。コレクションは空の状態から始めます。

```4d
$sitesWithDistance:=[]
```

続いて各結果を順に処理し、距離を計算して、オブジェクトをコレクションに追加します。

```4d
For each ($site;$sites)
    $distance:=geoDistance($site.coordinates;$city.coordinates)
    $sitesWithDistance.push({
        site : $site;
        distance : $distance
    })
End for each
```

その結果、返されるコレクションには観光地ごとに1つのオブジェクトが含まれ、それぞれが観光地のエンティティとその距離を保持します。

![返されるコレクションの構造](fig-10)

この構成にすると、結果リストが必要な値をすべて1つのオブジェクトから読み取れるため、インターフェース層がシンプルになります。

- 観光地の名称
- 関連する説明情報
- 計算された距離

このように、ORDAを使えば、コードをオブジェクト指向で読みやすく保ちながら、簡潔かつ効率的に地理空間検索を行えます。

### 使用している技術

この機能は、次の3つの技術を組み合わせて実現しています。

- OpenStreetMap：ベースレイヤーとして使用する地図データを提供
- 4DのWebエリア：フォーム内に地図を埋め込む
- Leaflet：地図を描画し、インタラクティブな操作を処理

Leafletは、Webページ上にインタラクティブな地図を構築するための軽量なJavaScriptライブラリです。地図の表示、マーカーの配置、地点間の線の描画、情報ポップアップの表示、ズームレベルの制御など、この機能に必要なものをすべて備えています。

![地図の表示に関わるコンポーネント](fig-12)

### 地図の作成

WebエリアはLeafletライブラリを参照するHTMLドキュメントを読み込みます。続いて、地図を選択した都市を中心に表示し、OpenStreetMapのタイルサーバーにベースレイヤーを要求します。そして、検索で返されたコレクションのエントリごとにマーカーを1つ作成します。コレクションの各オブジェクトは、観光地とその距離の組です。

![地図を作成する手順](fig-13)

完成した地図は完全にインタラクティブです。マーカーをクリックすると観光地の名称と都市からの距離を示すポップアップが開き、2つの位置の間に線を引くことができ、ズームレベルはユーザーが自由に操作できます。

## 4DのWebエリアでのインタラクティブな地図の表示

地図ページであるmap.htmlは、プロジェクトのResourcesフォルダーにあります。このページはLeafletライブラリを読み込み、表示を更新するための単一のJavaScriptエントリポイントであるupdateMap()を公開しています。

Webエリアは、ローカルで動作する4D Webサーバーからこのページを読み込みます。

```4d
#DECLARE->$url : Text
startMapServer()
$url:="http://127.0.0.1:8044/map.html"
```

URLは、フォームのOn Loadイベントで Webエリアに代入されます。

```4d
mapViewURL:=mapPageURL()
```

したがって、ページが読み込まれるのは一度だけです。その後に都市、観光地、検索距離が変更されてもページは再読み込みされず、表示されるデータだけが変わります。

![4DフォームとWebエリア内のページとのやり取り](fig-14)

### 4DからWebエリアへの動的データの送信

表示ごとに変わるのは、地点の座標とラベルだけです。buildMapData()メソッドは、これらを1つのオブジェクトにまとめます。

```4d
$data:={}
$data.src:={coords: $city.coordinates.toCollection(); label: $city.nameEN}
If ($site#Null)
    $data.dst:={coords: $site.coordinates.toCollection(); label: $site.nameEN}
End if
```

作成されるオブジェクトが持つプロパティは最大2つです。

- src：出発地点（都市）。座標とラベルを含みます。
- dst：目的地（観光地）。観光地が選択されている場合にのみ存在します。

![ページに送信されるオブジェクトの構造](fig-15)

オブジェクトは、pushMapData()メソッドによって静的ページに送信されます。このメソッドはWA EXECUTE JAVASCRIPT FUNCTIONコマンドを使用します。

```4d
WA EXECUTE JAVASCRIPT FUNCTION(*; "webMapView"; "updateMap"; *; $data)
```

このコマンドはページ上のJavaScript関数updateMap()を実行し、4Dオブジェクトを引数として渡します。JavaScriptオブジェクトへの変換は自動的に行われます。

Webエリアでのページの読み込みは非同期で行われるため、updateMap()を呼び出せるのはページの読み込みが完了してからです。そのタイミングはOn End URL Loadingイベントで通知され、状態はmapReadyフラグに記録されます。ページの準備ができていない間はデータを作成するだけで送信は保留し、読み込みが完了した時点で保留中のデータを送信します。

```4d
// On End URL Loading event
mapReady:=True
If (mapData#Null)
    pushMapData(mapData)
End if
```

その後のすべての操作（都市の選択、観光地の選択、距離の変更）では、データを作成し直し、ページの準備ができている場合にのみ送信します。

```4d
mapData:=buildMapData(citySelected; nearbySiteSelected.site)
If (mapReady)
    pushMapData(mapData)
End if
```

### Webエリア側での表示の更新

updateMap()関数は4Dから送られたオブジェクトを受け取り、2つのケースを区別して地図を更新します。

#### 1つの位置を表示する場合

出発地点のデータだけが渡された場合は、青いマーカーを1つ描画し、その位置を中心に地図を表示します。

```js
var srcMarker = L.circleMarker(data.src.coords, {
    radius: 8,
    weight: 2,
    color: '#fff',
    fillColor: '#1e66ff',
    fillOpacity: 1
}).addTo(overlay);
```

#### 2つの位置と経路を表示する場合

目的地のデータも渡された場合は、都市には同じ青いマーカーを残したまま、観光地に赤い2つ目のマーカーを追加し、2つを点線で結びます。

```js
var dstMarker = L.circleMarker(data.dst.coords, {
    radius: 8,
    weight: 2,
    color: '#fff',
    fillColor: '#ff8040',
    fillOpacity: 1
}).addTo(overlay);
var line = L.polyline([data.src.coords, data.dst.coords], {
    color: '#444',
    weight: 2,
    dashArray: '6,6'
}).addTo(overlay);
```

続いて、両方の地点が同時に見えるようにズームレベルを調整します。

```js
map.fitBounds(line.getBounds(), { padding: [100, 100] });
```

![updateMap()が扱う2つの表示ケース](fig-16)

これにより、選択を変更するたびに手動でパンやズームをしなくても、都市と観光地の位置関係がすぐにわかります。

## まとめ

このテクニカルノートでは、4Dで開発したアプリケーションにおける、地理空間検索機能の完全な実装を紹介しました。

このプロジェクトは、複数の機能を組み合わせて最新の位置情報ソリューションを構築する方法を示しています。

**4D.Vector**を使うと、GPS座標を緯度と経度を含む1つのオブジェクトとしてシンプルに表現できます。これにより、アプリケーションのすべてのメソッドで地理データを扱いやすくなります。

**ORDA**のおかげで、距離計算に基づくカスタムフォーミュラを使って、データベースのデータに対して直接検索を実行できます。ハーバーサイン公式を使ったgeoDistance()メソッドは、地球上の2つの位置の間の距離を確実に求めます。

**Leaflet**と**OpenStreetMap**による地図の動的な生成は、結果を視覚的に表現し、ユーザー体験を向上させます。ユーザーは都市周辺の観光地を、リストと地図の両方で確認できます。

ここで紹介した例は日本の都市と観光地を対象としたものですが、このアーキテクチャは、近くの顧客の検索、支店の検索、配送管理、車両の追跡、特定の地理的範囲内でのサービス検索など、さまざまな分野に応用できます。

このプロジェクトは、4Dアプリケーションが複雑なインフラを必要とせずに、最新の地理空間機能を効果的に組み込めることを示しています。4D、ORDA、4D.Vector、Web地図ツールを組み合わせることで、現在のビジネスアプリケーションのニーズに合った、シンプルで拡張性の高いソリューションを構築できます。
